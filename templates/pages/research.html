Research

{% include 'partials/byline.html' %}

Personal work on OS internals and low-level systems. It’s the other side of how I think about reliability.

1 This is actually how I started programming. For 13 years I’ve wanted to understand how software works on the inside, and since I grew up on PC games, the two met naturally. I began by poking at game memory with Cheat Engine for fun, then kept going as modern protections got harder. Along the way I built this toolkit and several others (many unpublished) for my own experiments. Still a hobby first: curiosity about internals, not a product line.

Outside product work I spend time on Windows kernel and user-mode internals: drivers, memory access, and how privileged code talks to the rest of the system.1 That curiosity feeds how I reason about boundaries, failure modes, and performance in production platforms.

Process attachment and memory layout (archived)

An earlier, separate study of a live game client: process attachment, module loading, memory layout, and overlay rendering, the same surfaces protection systems watch. Built as a Python tool with a custom loader; archived since 2023. Useful for understanding how untrusted code reaches another process’s address space.

Side projects (for fun)

A few open-source tools, frameworks, and hardware projects I’ve built outside work:

  • PyPulse: open-source framework for building Chromium-based desktop apps with a Python backend (on PyPI).
  • cefpythonX: a modern fork of cefpython, the Python bindings for the Chromium Embedded Framework, extended to run on Python 3.10–3.13.
  • real-tars: a real-life TARS robot (from Interstellar) with an embedded agent on ESP32-S3 + Radxa, a streaming voice/vision LLM, sensors, and a walking gait.
  • DiscordEasyCloner: desktop app to duplicate Discord servers, built on PyPulse.
  • Talk with Cletus Spuckler: a small GPT desktop app built to exercise PyPulse.
  • …and many more on GitHub.
